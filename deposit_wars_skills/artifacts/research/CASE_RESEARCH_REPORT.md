# TASK-002 全球奇葩租房案例研究报告

版本 1.0｜2026-10-22｜DRI：产品经理（调用 Rental Case Researcher）｜状态：研究完成；正式玩法设计待 CEO 批准

## 结论

首批录入 **56 个按事件去重的有效公开案例**，超过 50 条目标；共 54 个具体页面 URL。两条 URL 重复来自 [ABC 一篇包含三名不同受访者的报道](https://www.abc.net.au/news/2017-02-21/australians-share-their-rental-horror-stories/8277394)，事件、叙述和改编点不同。每条都有可访问的具体来源及查询日期。这里的「有效」意为公开来源支持该故事确实被讲述或报道；**Reddit、抖音自述不等于争议事实已获独立证实**。

较强的游戏素材不是单纯高金额或严重事故，而是**有可见矛盾、可操作检查、留证反击**的故事。例如[厨房旁的玻璃厕所](https://www.abc.net.au/news/2022-06-28/south-australian-building-codes-apartment-with-loo-in-kitchen/101190682)、[白天无法出入的房源](https://www.abc.net.au/news/2024-09-19/sydney-rental-rules-tenant-has-no-access-during-day/104364382)、[未点燃的蜡烛引发扣款](https://www.tenancydepositscheme.com/app/uploads/2025/04/Case_Study_The_Candle_clause_April_2025_v1.pdf)和[猫尿味受潮后再现](https://www.mydeposits.co.uk/content-hub/adjudication-case-study-carpet-cleaning/)都有明确的「看见 → 检查 → 证据」动作。推荐顺序详见 `TOP_10.md`，它是素材筛选，**不是正式关卡设计**。

## 方法与数据质量

- 手工定向查阅公开页面，按一个事件一行录入 `rental_cases.csv`；不批量抓取或绕过访问控制。CSV 不保留个人用户名、地址、联系方式、原图或长篇原文。
- 去重键为「事件主体 + 关键情节 + 时间/场景」；同事件的更新帖不重复计数，包含不同人物故事的同篇报道可分别计数。56 个 ID 唯一，54 个 URL 唯一，必填字段无空值，三个评分均在 1–5。
- 来源性质分为当事人自述/公开图帖、机构裁决摘要、媒体报道。机构摘要只证明该摘要记录了该争议和裁决；媒体采访中的主张仍归受访者，不能当独立核实的全部事实。
- 主题标签为一个主类：押金纠纷 21、黑心房东 8、恶毒房客 7、奇葩房间 6、奇怪室友 8、海外留学租房 6。标签是检索与剧本视角，不代表对任何真人的道德或法律定性。
- 荒诞程度 1–5：反常程度；视觉潜力 1–5：能否在单个 2D 场景识别；互动潜力 1–5：能否通过点按/工具/对照产生证据。评分为产品团队主观筛选，不是玩家数据。数据分析师职责的静态复核见 Quality Gate；游戏策划仅对 Top 10 的可玩动作提出初评。

## 覆盖与偏差

平台：Reddit 31、mydeposits 12、ABC 9、TDS 2、抖音 2。已知国家：英国 29、澳大利亚 9、爱尔兰 2、中国 2、新西兰 2、美国 1；11 条来源未说明国家，保持「未知」。样本明显偏向英语公开页面与押金纠纷，**不能称为全球发生率、市场规模或代表性调查**。Facebook 多数页面登录受限；TikTok 直接页面受 robots 限制；小红书未找到可独立核对的具体笔记，本轮均不计入有效案例。细节见 `SOURCE_GAPS.md`。

## 改编原则与风险

1. 从结构取灵感，重新创作人物、对话和美术，不复制真实帖子文案、图片或现实住房地址。
2. 把现实纠纷简化成可读的虚构规则与证据，不把故事改成法律建议；关于霉菌、电气、隐私和安全的事件避免轻视现实危害。
3. 押金反击需基于玩家实际发现的线索；若真实案例裁决不支持租客，应保留双向责任或改用虚构反转，不能把每位房东都预设为坏人。
4. 下一步先由 CEO 决定是否以 Top 10 进入正式玩法设计。未批准前不写正式首关、代码或广告实现。
