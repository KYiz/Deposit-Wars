# LEVEL-001 技术可行性与工作量预评

版本 1.0｜TASK-003｜程序员岗位按需预评；估算不是承诺，不含本轮开发

## 实现判断

固定剖面场景、五个热点的开合/放大层、证据卡与一一对应的扣款匹配，均可用候选 Phaser + TypeScript 的 2D 场景、输入事件与 UI 状态实现。最大风险不是算法，而是手机窄屏仍能看懂五处，以及 `phone compare` 不拖慢节奏。G2 前需确认引擎版本、平台嵌入要求和目标设备；本轮不安装依赖或写代码。

| 模块 | 难度 | 估计工程人日 | 风险控制 |
|---|---|---:|---|
| 场景适配、输入与局部放大层 | 中 | 2–3 | 点击与拖动等价；小屏两段平移；视觉热点实际可点击区扩大。 |
| 五个道具状态与反馈动画 | 中 | 2–3 | 统一四态配置，不做物理模拟；每个道具只保留 1 个主要动作。 |
| phone 证据卡与扣款匹配、押金结算 | 低～中 | 1.5–2.5 | 数据驱动的一一映射；误配无惩罚；运行内状态保留。 |
| 引导、提示、返回补查、基础无障碍 | 中 | 1.5–2.5 | 三层提示，触屏和键盘同通路。 |
| 浏览器/手机集成、修正 | 中 | 1.5–3 | 选定测试设备与浏览器；早测文字/触点；记录加载性能。 |
| **工程合计** |  | **8.5–14 人日** | 单名熟悉 Phaser/TS 的开发者、原创占位素材、无后端/广告 SDK。 |

美术占位到可试玩建议约 4–7 人日；QA/试玩组织与缺陷修正建议 2–3 人日，均可与部分工程交叠。整体日历时间需在 G2 批准、人员工时与验收设备确定后排期。估算不含正式商店/平台对接、广告、音频授权、本地化、完整美术和第二关。

## G2 可玩原型的最小范围（待 CEO 审批）

- 单房间 A 画面灰盒，五处热点及各自唯一可验证动作。
- 1 个 phone 对照/记录机制；不做湿度仪和放大镜。
- 五张原创证据卡、五张扣款卡、房东表情/短气泡、押金结算。
- 首个热点引导、分级提示、误配恢复、部分结算后回房。
- 英文短文案；桌面鼠标/键盘与手机触屏的最小适配。
- 原型行为埋点（本地匿名记录即可）；不接广告、账号、云存档或平台 API。

**切除规则**：若排期紧，先缩动效及装饰，不删证据闭环与恢复路径；如果必须降为 3 缺陷，需回到 G1 由 CEO 重新批准，因为与本次五缺陷验收标准冲突。

## 待验证风险

1. 小屏无法同时呈现五处视觉线索与大触区；需要在首个手机试玩前做分辨率走查。
2. phone 对照若每次重复多点会压缩搞笑占比；原型用一次点击完成比较，再以事件计时决定是否简化。
3. “入口限制”与“有蜡烛无损害”的叙事涉及现实租赁制度，但关内只凭虚构承诺和可见事实判定。文案审阅不能把它说成普遍法律结论。
4. CrazyGames/Poki 具体接入和商业条款可能变化，G2 前由发行运营重新核官方规则；此工作量不覆盖正式上线。
