# TASK-001 产品判断与一房间验证草案

版本 0.1｜2026-10-22｜状态：研究建议，未获 G1 批准｜DRI：产品经理

## 建议结论

**建议有条件进入低成本的一房间玩法原型设计**，先验证玩家是否愿意把缺陷转成证据、并享受反击房东的结果。现实租房痛点与同类观察游戏存在，但没有证据证明 Deposit Wars 的题材能吸引平台玩家、取得推荐或形成广告收益。因此建议进入 G1 的是可验证设计，不是承诺正式制作或发行。

## 受众与定位

首要假设受众为能理解英文租房情境的年轻租客；留学生是可测试子群。定位一句话：在荒诞租屋中识破缺陷，检查并保存证据，在房东扣押金时用事实反击。幽默要来自可见的矛盾与夸张反应，避免要求玩家掌握某国租赁法律。现实背景见 [英格兰租房调查](https://www.gov.uk/government/statistics/english-housing-survey-2023-to-2024-rented-sectors/english-housing-survey-2023-24-rented-sectors) 和 [NUS UK 学生住房调查](https://www.nus.org.uk/housing-survey-2024)；它们不能证明游戏需求。

## 最小验证范围（提议）

- 一个 2D 房间、五个可见缺陷、至多三种检查动作、五张证据卡、一次押金结算/反击。进入关卡后尽快允许点按；不做冗长文字教程。
- 每个缺陷包含视觉线索、可操作检查、证据反馈、对应房东指控与反驳。错误点击应能恢复，不出现死局。
- 英文基础文案；桌面鼠标和手机触控均需设计，技术仍以 Phaser + TypeScript 为候选，待 POC 决定。
- V1 不纳入 3D、Steam、账号、后端、法律咨询、付费服务或广告 SDK。

## 待测判断与接受标准草案

1. 玩家不经解释能说清目标与「证据为何能反击」；有卡关则记录具体节点，不强行给通过率行业基准。
2. 与只找缺陷的简化版本比较，检查和反击环节是否提高主观趣味且未明显拖慢通关；小样本只做方向判断。
3. 手机端能看到线索、点中目标、读懂证据卡；记录误触和放弃位置。
4. 广告仅考虑自然关卡边界，必须有无广告仍可通关的设计。具体 SDK、平台及变现策略另经 CEO 审批。

## G1 前 CEO 需决定

1. 是否批准进入 G1 的一房间规则与纸面/灰盒设计（推荐：批准有限验证）。
2. 平台策略暂定双平台候选；正式发行前是否愿意考虑 Poki 网页独占，或优先 CrazyGames / 非独占路径。现在无需签约。
3. 英文优先、留学生作为子群的测试定位是否接受；若另有首发地区，需调整样本与文化语境。

主要风险：题材共鸣不等于游戏兴趣；情境推理已有强竞品；内容生产可能比纯找茬贵；手机线索可读性；平台筛选与广告收益未知；Poki 独占与双平台发布冲突。来源与比较详见 `COMPETITOR_MATRIX.md`、`ASSUMPTION_LOG.md`、`../publishing/PLATFORM_CHECKLIST.md`。查询日期：2026-10-22。
