# 双视角找茬 Demo｜调查界面 UI Skill

## 1. 目标与页面边界

设计角色选择之后的**纯房间调查界面**。玩家进入租客或房东视角后，注意力应集中在出租屋现场、三个可调查线索和当前调查目标上。

- CASE FILE 档案夹与身份选择卡只属于独立首屏，不出现在本调查界面。
- 本界面不设置右侧档案栏。
- 线索清单、答题、答案反馈和结局均按需显示，不常驻占据房间空间。
- 这是当前 Demo 的视觉与交互提案，待 CEO 评价；不是已冻结的 V1 规范。
- 所有房间、角色、金额和事件均为虚构游戏内容。

## 2. 页面构成

### 顶部品牌栏
- 左侧显示 DW / IDWi 项目标志（以项目现有资产为准，不凭空设计正式商标）。
- 显示游戏名：`一间好房，两份真相`。
- 显示 `PLAYABLE DEMO` 状态标签。
- 右侧短句：`同一间房 · 不同的视角 · 不同的答案`。
- 顶栏应轻量，不能压缩房间主画面。

### 游戏状态栏
放置在房间画面上方，作为单行或分组清晰的横向信息区：
- 当前视角：`租客` 或 `房东`。
- 房间名称：`海景公寓 · 301室`（虚构案件名）。
- 进度：`0/3`，配三个未完成状态圆点。
- 当前角色目标：
  - 租客：`找出广告与现场的矛盾，追回押金。`
  - 房东：`找出问题并选择实际整改方式。`
- 角色目标根据当前视角动态变化。
- 不显示右侧档案栏，不把身份选择卡放进状态栏。

### 房间主画面
- 画面主体为完整出租屋插画，视觉面积最大。
- 采用暖色、生活化、略带漫画线稿的插画风格：暖米色墙、木门与木柜、粉色窗帘、深青绿色沙发、橘色地毯、绿植与暖光吊灯。
- 场景构图需清楚、物件有辨识度，不要被 HUD 或装饰遮挡。
- 原项目房间 SVG 设计尺寸为 `1200 × 670`，保持该比例缩放；窄屏优先缩放，不裁掉右侧门锁。
- 插画应作为调查场景，而不是 CASE FILE 拼贴图；房间内部不出现档案夹、证据照片板或角色选择卡。

### 三个可调查热点
热点覆盖在房间对应位置，使用深墨紫圆形编号、浅色描边与明显的焦点轮廓：
- `01`：帘子。
- `02`：墙画。
- `03`：时钟门锁（按实际场景中项目定义的第三处谜点定位，保证门锁/相关线索完整可见）。

热点需足够大，可用鼠标、触屏与键盘操作；不要求精准点击细小物件。未破解为深色圆形，破解后转为绿色状态。悬停、键盘焦点应有清晰轮廓提示。

### 底部操作
- 左下角：珊瑚红按钮 `给我一点提示`。
- 右下角：深墨紫按钮 `切换视角`。
- 按钮覆盖在画面边缘的留白或独立底栏中，不遮挡关键线索。
- 提示按钮定位到第一个尚未破解的热点，并给出简短文字提示。
- 切换视角按钮切换租客/房东路线；切换是否保留已破解进度需遵循项目当前规则，不能在视觉稿中暗示未实现的状态。

### 按需出现的调查弹窗
点击任一未破解热点后，显示居中或靠近热点的清晰对话框：
- 观察句。
- 一个与场景细节相关的问题。
- 两个可选答案。
- 错误选项被淡化并禁用，显示“再看一眼”的反馈；不扣分。
- 正确选项显示现场与广告的矛盾（租客）或可执行整改依据（房东）。
- 提供明确的关闭/继续操作；支持 `Esc` 关闭。
- 弹窗打开时，背景房间仍可辨认，但不能让玩家误以为其他控件仍可同时操作。

### 完成状态与结局
- 三处线索全部破解后进入结局弹窗。
- 租客路线：显示虚构的 `$300` 游戏押金追回结果。
- 房东路线：显示 `3/3` 项问题整改结果。
- 结局提供重玩或切换视角入口。
- 所有金额和结局仅为虚构游戏反馈，不是现实承诺。

## 3. 视觉规范

| 项目 | 规范 |
|---|---|
| 页面底色 | 暖纸色 `#f4f0e7` |
| 主要文字与边框 | 深墨紫 `#22243b`，允许接近色 `#24243f` |
| 强调色 | 珊瑚红 `#d96762` |
| 租客状态色 | 鼠尾草绿 / 青绿色，需与背景保持足够对比 |
| 房东状态色 | 柔和橘色 |
| 房间配色 | 暖米色墙、木色门柜、粉红帘、深青绿沙发、橘色织物、植物绿 |
| 线条 | 清晰漫画线稿，重点区域使用粗描边 |
| 阴影 | 克制的硬边纸卡阴影；避免过度装饰 |
| 字体 | 系统无衬线；优先设备已有的 DM Sans、Noto Sans SC，否则使用 sans-serif |
| 外部资源 | Demo 不强制下载外部字体或第三方素材 |

## 4. 页面布局与响应式

- 最大页面宽度建议 `1600px`。
- 游戏区域两侧留白建议 `clamp(20px, 4vw, 70px)`。
- 桌面端：顶部品牌栏、游戏状态栏、完整房间主画面与底部操作。
- `≤950px`：缩短品牌栏文案、压缩状态栏间距；房间仍保持完整比例。
- `≤590px`：减少外边距与字号，状态信息允许分行；底部按钮保持易触达且不覆盖线索。
- 窄屏下优先让场景完整缩放；如空间不足，可将操作按钮移到房间下方的独立操作条，不能裁掉门锁。
- 热点跟随 SVG 画布坐标缩放，不使用与屏幕无关的固定绝对位置。
- 页面应避免水平滚动。

## 5. 交互流程

1. 从 CASE FILE 首屏选择身份后进入本页。
2. 根据所选身份显示当前视角、角色目标和对应的题目内容。
3. 玩家可按任意顺序调查 01、02、03。
4. 未选择身份时不应进入调查界面；如因测试直接访问，应显示明确的返回选身份提示。
5. 点击热点，弹出对应题目。
6. 选错时显示轻量提示，错误选项禁用；正确选项仍可选择。
7. 选对时更新该线索状态、进度和热点颜色。
8. 三条线索完成后显示角色专属结局。
9. `给我一点提示` 指向第一个未破解热点；全部完成后再次打开结局。
10. `切换视角` 切换到另一角色路线；其进度处理方式以项目实际实现为准。
11. 支持鼠标、触屏、Tab、Enter/Space；弹窗支持 `Esc` 关闭。

## 6. 可达性要求

- 所有热点与操作按钮使用语义化 HTML 按钮。
- 热点提供清晰的 `aria-label`，例如“调查线索 01：帘子”。
- 进度更新可通过适当的 live region 告知辅助技术。
- 弹窗使用 `role="dialog"`，标题与弹窗关联；打开时管理焦点，关闭后将焦点还给触发热点。
- 键盘焦点必须明显可见，选中/破解状态不能只依靠颜色表达。
- 文字与背景保持足够对比；触屏目标应足够大。
- 房间 SVG 应提供整体描述；纯装饰元素不重复朗读。

## 10. 当前限制

本文件定义视觉与交互要求，不等于可运行的游戏代码。静态概念图不具备真实点击、答题、状态更新或弹窗功能；实际行为需要由 HTML/CSS/TypeScript 实现并测试。
