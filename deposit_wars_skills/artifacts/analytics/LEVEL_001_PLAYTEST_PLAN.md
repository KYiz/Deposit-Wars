# LEVEL-001 试玩验证计划

版本 1.0｜TASK-003｜数据分析师按需制定；**尚无试玩结果**

## 目标与样本

G2 如获批准，用 8–12 名便利样本先做可用性探索，兼顾桌面/手机、海外年轻租客或留学生经历与无该经历者。样本量只支持发现明显问题，不支持市场需求或留存推断。先让受试者独立玩，不解释热点；记录同意后的匿名行为时间与一句主观反馈，不收房屋地址、租赁经历详情或个人身份。

## 事件口径

`level_start`、`first_hotspot_open(defect_id, t)`、`defect_revealed`、`evidence_collected`、`hint_shown(level, defect_id)`、`face_landlord`、`evidence_match(correct, defect_id)`、`return_to_room`、`level_finish(returned_amount, elapsed_s)`。事件只需会话内匿名 ID；不上传外部服务。观察员另记“笑点反应/困惑点”但不得把主观微笑当客观市场指标。

## 原型验收阈值（设计假设，不是行业基准）

| 指标 | 计算与目标 | 触发修订 |
|---|---|---|
| 首次互动时间 | 起始到任一热点首次打开；≥80% 受试者 ≤30 秒 | D1 不明显时加强帘子动势/点击区，减少开场文本。 |
| 完整闭环 | 无主持人口头帮助下完成 5 取证+5 反击；≥70%，完成者中位 3–5 分钟 | 若超时，按 GDD 修剪动作与动画；若卡在匹配，改证据卡图标。 |
| 证据关系理解 | 结束后能说出至少 4/5 个“现场事实对应哪项扣款”；≥75% | 短化文案/强化图像对应；不加法律说明。 |
| 找茬与反击时长占比 | 观察/验证 60–80%，反击 20–40% | 偏离 70/30 超过 10 个百分点则调整节奏。 |
| 提示依赖 | ≥60% 玩家在前两处缺陷无需第二级动作提示 | 优先修视觉线索和点击区，不把提示当内容。 |
| 笑点感知 | 访谈中“至少两处让我觉得荒诞或好笑”≥70% | 查具体缺陷表现，避免用更多文字解释笑话。 |
| 移动端可操作 | 手机上每名玩家五处均能点击；无反复误触阻塞 | 扩大点击区/分屏平移或重排 UI。 |

阈值用于 G2 继续/修订决策，8–12 人数据应附原始计数与置信限制，不把百分比写成普遍结论。记录每个缺陷的中位发现时间、失败动作、提示次数、误配次数，尤其检查 D5 是否比其他四处显著拖慢。

## 验收流程

桌面和手机各至少 3 名观察，覆盖首次玩家。完成后数据分析师整理原始匿名事件、观察记录和逐项结论；游戏策划根据具体阻塞点改 GDD；QA 复测“补查不丢证据”与误配无惩罚。只有原型实测通过或记录可接受偏差，才能声称体验指标达到，不得以本计划替代结果。
