# TASK-015：场景内找茬交互与轻量 HUD

版本 1.0｜2026-10-28｜G2 本地 Demo 实施稿｜DRI：游戏策划

## 从玩家视角修正的问题

TASK-014 把拖动放进独立案卷弹窗，房间里仍是五个编号，找东西实际变成“点正确编号”。更严重的是编号和大按钮已烙在原房间参考图中，删 HTML 无法清除。TASK-015 把观察与操作还给房间：玩家从已有帘子、画框、柜门、门锁和茶几摆设入手，直接在图上拖动物件；具体发现留在原地。唯一常驻 UI 是一条进度胶囊和四个小操作图标。提示只在请求或闲置后出现，不把谜底常驻写在画面上。

## 输入与反馈

| 物件 | 直接操作 | 场景反馈 | 后续检查 |
|---|---|---|---|
| 帘子 D1 | 向右拖 | 帘子被拉开，露出相邻厕所 | 自动记录“卫浴与餐桌同框” |
| 墙画 D2 | 向上移开 | 露出旧水痕与蘑菇 | 再沿水痕下拖，确认旧渗漏 |
| 柜门 D3 | 向右拉开 | 柜内折叠床和额外鞋子出现 | 自动记录隐藏角落 |
| 门锁 D4 | 向下试门把 | 锁住 | 再向上翻门牌，看到 9–17 限制 |
| 茶几 D5 | 向上拿开玻璃罩 | 看见小蜡烛 | 再查烛芯、擦看桌面，无烧痕 |

鼠标或手指必须产生足够远的位移；玩家可以向任意方便的方向移动，避免猜手势方向。单点不会取证。短拖动复位，不扣款。键盘/辅助输入聚焦物件后按 Enter 可执行等效动作；1–5 只负责聚焦，不直接解谜。最后一步完成时证据自动存入 Phone，减少重复按钮。Phone 和扣款核对仍沿用已验收的 `GameSession` 规则，租客/房东共享现场与物件互动，仅叙事不同。
