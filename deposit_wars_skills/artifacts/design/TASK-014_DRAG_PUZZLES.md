# TASK-014：拖动解谜与案例映射

版本 1.0｜2026-10-28｜状态：G2 本地 Demo 实施稿｜DRI：游戏策划

## 玩法判断

旧 Demo 五个编号大多是“点开窗口，再点动作文字”。这能验证结算逻辑，却没让房间物件形成谜题。新流程为：在同一张插画房间图发现异常 → 点物件区域进入案卷式局部场景 → 把物件拖到目标 → 看到新画面 → 完成必要的后续检查 → Phone 记录证据 → 核对扣款。拖动目标和反馈保持在房间/案卷的暖纸张、深蓝描边视觉体系中。房东与租客共用客观现场，只改变目标、叙事和最后核对措辞。

## 可玩性与补救

- 拖错位置立即复位，无金额损失；每一步都有物件和目标标签。
- 手机以 Pointer Events 拖动；无法拖动或键盘操作时可点等效动作按钮。第二级提示说明操作。
- 每一步有独立可见揭露；只完成全部步骤才开放 Phone 记录。
- 五张证据与五项虚构扣款保持一一对应；允许提前核对、回房补查和部分结算。

## 未解决的视觉与验证问题

局部场景使用 CSS/符号搭建，属于可玩原型美术。若进入正式精修，仍需把原图中的帘子、墙画、柜门、门牌、蜡烛各制作检查前/后插画，并用真实玩家验证第一眼线索是否足够。G3 真人试玩未获批准，本稿不声称玩法有趣性已得到玩家验证。
