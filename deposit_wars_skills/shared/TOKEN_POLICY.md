# 低 Token 多 Agent 协作协议

## 每轮输入顺序
1. 仅发本岗位 `SKILL.md`、最新 `PROJECT_STATE.md`、当前任务卡。
2. 只按 `inputs` 引用必要上游工件；不注入其他 7 个完整岗位技能。
3. 把完成结果保存至文件后，跨角色只转发不超过 200 字的 `HANDOFF` 摘要和路径。

## 推荐上下文预算（建议值，非系统硬限制）
- 调度决策：约 300–700 tokens（状态 + 当前任务卡 + 交接摘要）。
- 单岗位执行：按任务规模约 1k–4k 输入 tokens，超出需说明原因。
- 审核：只提交验收标准、差异文件、证据；不要重放全部历史。

## 防浪费
- 不让 8 个 Agent 对同一个问题都做完整调查；只由 DRI 深入研究。
- 不反复扫描完整 repo；先看目录、变更文件、必要测试。
- 简报输出结论/依据/待批准项；大型报告落地文件，不贴入聊天。
- 优先模型分层：路由、分类、格式检查用轻量模型；架构争议/复杂代码/战略决策才用高成本模型。
- 缓存稳定规则文件，不在每次调用重新生成；可对重复项目上下文做摘要压缩。
- 未经评估不要盲目并行；并行会降低时间，但可能增加总 token。
