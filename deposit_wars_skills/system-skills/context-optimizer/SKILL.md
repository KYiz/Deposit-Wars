# Context Optimizer — 最小上下文与断点交接

## 定位
这是项目经理的上下文管理 Skill，**不是独立 Agent**。目标是减少重复上下文开销，非承诺某种固定 Token 节约比例。服从 `shared/TOKEN_POLICY.md`、`shared/PROJECT_STATE.md`、`shared/DECISION_RIGHTS.md`。权威文件优于聊天摘要；不要把摘要改写成已验证事实。

## 触发
新任务指派、岗位交接、用户说“继续项目”、会话重启、额度耗尽后手动恢复，或输入变得冗长。

## 必须保留的 8 类信息
1. 项目 ID、阶段 Gate、任务 ID、任务状态。
2. CEO 已批准的不可变限制：2D 网页版 V1；3D Steam 版暂为未来衍生，未经批准不进入实施。
3. 任务目标、唯一 DRI、相关依赖与验收条件（DoD）。
4. 权威输入文件及具体路径，优先定位到标题/章节/行区间。
5. 已完成工件的路径、变更摘要及 Git commit/diff（如存在）。
6. 真实运行过的测试命令和结果；未运行项要显式列出。
7. 待解决风险、阻塞、CEO 待批事项和返工次数。
8. 下一条可执行动作与停止条件。

## 压缩策略
1. 先读取 `shared/PROJECT_STATE.md`、当前任务卡、最新一次交接卡；其他文件只根据清晰的引用读取。
2. 先将信息分为 `已验证事实 / CEO 决策 / 假设 / 待核查` 四类；相互冲突的说法保留冲突并附来源，不擅自合并。
3. 重复背景去重，历史过程只留最新结论及追溯路径；不要复制全部日志/聊天记录/代码。
4. 代码交接给文件路径、符号名、diff 概要与复现命令；文档交接给章节、结论、限制；市场交接给时间与来源而不是虚构结果。
5. 默认交接摘要控制在约 300–500 中文字（上下文复杂时可超出），日志和证据保留在文件中并提供路径。
6. 只加载当前 DRI 的岗位 Skill、触发的管理 Skill 和与任务直接相关的文件；不一次性读 8 个岗位 Skill。
7. 交接时以原子文件写入方式保存新的状态/交接（若工具支持），避免中断时产生半成品。历史记录不得在未经 CEO 授权情况下清空。

## 交接包输出模板
```text
项目: Deposit Wars | Gate: Gx | TASK-xxx | 状态: ...
DRI / 下一个岗位: ...
已批准约束: ...
已验证事实: ... [来源路径]
本轮变化: ... [文件路径 / Git diff]
验证: <命令与 PASS/FAIL/NOT_RUN>
未完成 / 风险: ...
CEO 待批: 无 / ...
下一条动作: ...
停止条件: ...
```

## 人工额度恢复协议
收到“继续项目”时，重新读取磁盘状态和 Git diff，而非仅相信上一轮对话。若上次中断：先核对是否已产生副作用，再继续剩余原子步骤。不要自动重试额度、后台轮询或规避平台限制。若缺少任务状态或前置依赖，先让 Workflow Controller 建立/修复最小记录。

## 质量红线
摘要中不能抹掉失败测试、未完成审批、合规风险和明确的未知项；不能把“建议”升级成 CEO 决议，也不能声称上下文压缩改变实际平台计费方式。
