# Rental Puzzle Designer / 租房案例玩法转译

用于把 `artifacts/research/rental_cases.csv` 中的案例母题转为短局、双视角、逐关升级的动作。先读取当前任务卡、`shared/PROJECT_STATE.md` 和游戏策划岗位 Skill；只按任务所需读取案例行及源文核查记录。项目经理仍是任务调度入口，游戏策划仍是玩法 DRI。

## 关卡路线先于事件卡

1. 先提出关卡数、每关每视角的独立事件数和总数，核对当前 CEO 已确认的规模目标；规划不等于批量制作获批。房东路线要有租客/室友侧的独立目标、现场变化和责任判断，不能把租客路线换台词。
2. 每关注明场景、剧情位置、新操作动词、旧机制复用、操作层数、跨区域或道具依赖、证据判断难度、预计时长（标假设）和通关条件。难度增加来自思考与操作，不靠更多文字、编号热点、藏得更小或误触惩罚。
3. 限制每次只引入一种主要新手势或判断，首个实例给画面内示范，此后逐步撤去提示；拖错可复位、反复检查不罚分、两级提示只指出可疑区域再指出动作。
4. 对案例按 `已核实事实 / 当事人自述 / 双方争议 / 纯虚构` 标界。报道里的室友、房产销售或第三方事故若改成租客行为，必须明确是虚构改编；不能把全部房东路线事件称为已证实的恶意租客。

## 转译方法

1. 区分来源事实、受访者自述、游戏虚构设定。每条游戏事件保留 Case ID、原来源 URL、查询日期和改编边界；不把虚构合成房间称为真实案件。
2. 从案例中提炼一个玩家能在房间图上看见的异常信号，例如水痕、额外拖鞋、反常门把。信号应在拖动前出现，不能靠旁白直接给答案。
3. 每个事件写明拖前可见线索、物件的房间位置和可拖动范围、手势（拉开、掀起、移走、对齐、组合）、放手后的命中条件、逐步画面状态、复位方式。只有谜题确实需要定点组合时才设目标区；普通遮挡物允许向合理方向拖开，避免像按钮。多步检查各有不同发现。触控与键盘有等效路径，动作完成前不能记证据。
4. 写清租客与房东各自为何调查、看到同一事实后如何作答。租客保存现场反驳虚构扣款；房东识别错误宣传或不合理扣款并整改。不同视角不改变客观证据。
5. 最后才连到 Inspection Phone 的广告/现场对照、证据卡、扣款卡与结算。每张证据只解决一项指控；不输出真实法律判断。

交付关卡路线图和逐事件可实现目录，再为进入制作的事件交谜题卡：`Case ID/来源状态/URL/查询日 → 事实与改编边界 → 拖前线索 → 物件位置/热区/手势/放手条件 → 状态变化与复位 → Phone 证据或反证 → 双视角反馈 → 提示/触控/键盘 → 测试步骤/美术状态清单`。没有可靠来源的内容标虚构或待核实，不杜撰来源。未获制作批准的关卡只交规划，不假称已可玩。

首关实例和来源映射见 `artifacts/design/TASK-014_DRAG_PUZZLES.md`；关卡规模与物件目录示例见 `artifacts/design/TASK-016_LEVEL_ROADMAP.md`、`TASK-016_DRAG_OBJECT_CATALOG.csv`。本 Skill 不改变 `shared/WORKFLOW.md`、`shared/DECISION_RIGHTS.md`、原岗位 Skill 的权限，也不授权 G3、扩关或发布。
